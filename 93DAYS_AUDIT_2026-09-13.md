## High-priority findings

### 1. Memory authoring vertical slice was incomplete

`character-remembers` existed in the domain union and runtime projection, but the project-reference validator did not handle this effect type. As a result, a structurally valid memory effect could be rejected by the normal `move/addEffect` authoring path.

The general Outcome Effects panel also did not expose `character-remembers`, so authors could not create the effect from the UI.

This audit follow-up closes both gaps and adds store-level regression coverage.

### 2. Architecture documentation is one consolidation behind the implementation

`93DAYS_ARCHITECTURE_V10.md` still lists A31/A32 as the next vertical slices, while `93DAYS_A31_A32_MEMORY_IMPLEMENTATION.md` records them as implemented. The implementation note should be folded into the main source-of-truth architecture document in the next documentation consolidation.

### 3. Reaction memory scoring still ignores A32 salience

The current `memory-tag` Reaction consideration checks whether any matching memory exists. Old low-salience memories therefore still contribute the same weight as fresh or reinforced memories. The next cognition slice should optionally evaluate memory-tag considerations against derived salience at an explicit runtime moment and retain explanation traces.

### 4. Authored/editor/runtime persistence is still physically mixed

`NarrativeProject` remains the temporary schema-v2 envelope for authored definitions, editor state and runtime-ish cognition. This is already documented as temporary, but it becomes a scaling and migration risk before autonomous Living Simulation. Persistence projection cleanup remains a required gate.

### 5. Upstream integration risk is growing

The branch is 26 commits behind `develop`, and the draft PR is currently not mergeable. Upstream has already moved framework/tooling versions while the 93 Days branch continues on its older dependency set. Do not mix a large upstream synchronization with a gameplay/domain vertical slice; perform the synchronization as a dedicated integration task with CI and conflict review.

## Recommended next order

1. Finish A31/A32 authoring closure and keep CI green.

5. Synchronize `develop` in a dedicated integration branch/commit series before the divergence grows further.
